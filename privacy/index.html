Kapsam ve mevcut durum

Bu politika Ece Eczanesi İletişim uygulamasının mevcut WhatsApp Business Platform / Cloud API webhook alıcısını açıklar. Sistem geliştirme aşamasındadır ve henüz production müşteri mesajlaşmasına açılmamıştır. Gelecekte eklenebilecek özellikler bu açıklamanın kapsamında değildir.

İşlenen bilgiler ve amaç

Webhook endpoint'i, WhatsApp üzerinden Meta tarafından iletilen olayları alır. Bu olaylar telefon numarası, mesaj içeriği, mesaj kimliği ve olay türüne bağlı diğer alanları içerebilir. Gelen olaylar entegrasyonu çalıştırmak ve yinelenen mesajların tekrar işlenmesini önlemek amacıyla işlenir. İçeriğin istek sırasında alınması, kalıcı olarak saklandığı anlamına gelmez.

Kalıcı saklama ve diagnostic loglar

Mevcut receiver mesaj içeriğini kalıcı olarak saklamaz. Idempotency, yani yinelenen mesajları tanıma amacıyla yalnızca mesaj kimliğinin SHA-256 hash'i SQLite'ta tutulur. Bu hash kaydı mesaj gövdesi veya telefon numarası içermez; tüm verilerin anonim olduğu iddiasında bulunmuyoruz. Bu kayıtlar için doğrulanmış bir otomatik silme süresi burada belirtilmemektedir.

Telefon numarası, mesaj gövdesi, reçete, webhook payload'ı, App Secret veya access token diagnostic loglara yazılmaz. Mevcut implementasyonda media dosyaları indirilmez.

Güvenlik

Webhook isteklerinde Meta'nın X-Hub-Signature-256 başlığı kullanılarak HMAC-SHA256 imza doğrulaması uygulanır. Bu kontrol webhook isteklerinin doğrulanmasına yönelik bir önlemdir; mutlak güvenlik garantisi veya KVKK/GDPR uygunluk sertifikası değildir.

Diğer hizmetler

WhatsApp mesaj iletimi Meta / WhatsApp altyapısı üzerinden gerçekleşir. Bu politika mevcut uygulama receiver'ını açıklar; Meta / WhatsApp'ın ve site barındırma sağlayıcısının kendi veri işleme ve saklama uygulamalarını kapsamaz. Bu uygulamalar ilgili sağlayıcıların politikalarına tabidir.

English

Scope and current status

This policy describes the current WhatsApp Business Platform / Cloud API webhook receiver for Ece Eczanesi İletişim. The system is in development and has not yet been opened for production customer messaging. Features that may be added in the future are outside this description.

Information processed and purpose

The webhook endpoint receives WhatsApp events delivered by Meta. These events may contain a phone number, message content, a message identifier and other fields depending on the event type. Events are processed to operate the integration and prevent duplicate message processing. Receiving content during a request does not mean that it is stored persistently.

Persistent storage and diagnostic logs

The current receiver does not persist message content. Only a SHA-256 hash of the message identifier is stored in SQLite for idempotency, meaning recognition of duplicate messages. This hash record does not contain the message body or phone number; we do not claim that all data is anonymous. No verified automatic deletion interval for these records is specified here.

Phone numbers, message bodies, prescriptions, webhook payloads, the App Secret and access tokens are not written to diagnostic logs. The current implementation does not download media files.

Security

Webhook requests are verified using HMAC-SHA256 and Meta's X-Hub-Signature-256 header. This is a measure for verifying webhook requests, not a guarantee of absolute security or a certification of compliance with KVKK or GDPR.

Other services

WhatsApp message delivery takes place through Meta / WhatsApp infrastructure. This policy describes the current application receiver; it does not cover the separate data processing and retention practices of Meta / WhatsApp or the site hosting provider. Those practices are subject to the respective providers' policies.
